# Plano de Testes E2E — Jev Conversacional (ADK) + Jev-Trader (Typesafe) + Interface

## Goal
Definir e automatizar o plano de testes end-to-end do sistema completo: **Jev Conversacional (Google ADK, modelo gemini-3.8-flash)** orquestrando **Jev-Trader (Typesafe `jev-latest`)**, com **memória persistente** (`MemoryService`) e **web search grounding** (`google_search`), validando tanto API/CLI quanto interface web (`adk web`). Após aprovação, incluir o parâmetro de modelo no `.env` e implementar a suíte.

## Success Criteria
- [ ] `GEMINI_MODEL=gemini-3.8-flash` parametrizado em `jev_conversacional/.env` e lido por `agent.py` (não hard-coded).
- [ ] Suíte E2E em `tests/e2e/` com 3 camadas: **API (Runner)**, **CLI (`adk run`)**, **Interface Web (`adk web` + Playwright)** — executável via `uv run pytest tests/e2e -m e2e`.
- [ ] 15 cenários E2E cobrindo: saudação sem ticker, recomendação PETR4 swing, gate `evento_binario`, ticker inválido, follow-up memória cross-session, web search com fontes, e disclaimer CVM.
- [ ] Mocks para `TYPESAFE_API_KEY` ausente (usa `mock_answers`) e para `google_search` offline; modo `live` com chaves reais roda os mesmos cenários contra `jev-latest` e `gemini-3.8-flash`.
- [ ] CI gate: `pytest tests/test_jev_trader.py tests/test_conversacional_adk.py` (unit) + `pytest -m e2e --env=mock` verde; relatório `html` + traces Playwright arquivados.

## Constraints And Non-goals

**Constraints:**
- Não expor chaves em log; testes live devem ler `GOOGLE_API_KEY`/`TYPESAFE_API_KEY` do `jev_conversacional/.env` via `python-dotenv`, nunca hard-coded.
- `adk web` é dev-only (não prod); interface E2E deve rodar contra `adk web` local em porta efêmera, não contra deploy Cloud Run.
- Camada SystemOne (Jev-Trader) continua mockável: E2E mock não chama `https://api.typesafe.ai/v1/systemone` quando `TYPESAFE_API_KEY` ausente.
- Playwright headless para interface; evitar `adk web` em CI sem `GOOGLE_API_KEY`.
- Idioma dos asserts PT-BR (`Recomendação`, `Disclaimer`) para validar orquestrador.

**Non-goals:**
- Load/stress test (k6/locust), teste de `VertexAiMemoryBankService` (requer GCP Project), teste visual pixel-perfect.

## Recommended Approach

### 0. Parametrização do modelo (pre-requisito E2E)
- Atualizar `jev_conversacional/.env.example`:
  ```
  GEMINI_MODEL="gemini-3.8-flash"
  ```
- Atualizar `jev_conversacional/.env` (já com chaves) adicionando `GEMINI_MODEL="gemini-3.8-flash"` sem sobrescrever `GOOGLE_API_KEY`/`TYPESAFE_API_KEY`.
- Refatorar `agent.py`:
  ```python
  import os
  from dotenv import load_dotenv
  load_dotenv()  # lê jev_conversacional/.env quando rodado via ADK
  GEMINI_MODEL = os.getenv("GEMINI_MODEL", "gemini-3.8-flash")
  root_agent = LlmAgent(model=GEMINI_MODEL, ...)
  ```
- Smoke: `.venv/bin/python -c "from jev_conversacional.agent import root_agent; assert root_agent.model=='gemini-3.8-flash'"`

### 1. Estrutura E2E
```
tests/e2e/
  conftest.py          # fixtures: adk_runner (InMemory services), mock_google_search, tmp .env
  test_e2e_runner.py   # API via Runner.run_async (sem UI, mais estável)
  test_e2e_cli.py      # CLI via subprocess .venv/bin/adk run jev_conversacional "query"
  test_e2e_web.py      # Interface via Playwright contra adk web
  fixtures/
    scenarios.json     # 15 cenários declarativos
```

### 2. Cenários (15, declarativos em `scenarios.json`)
1. `saudacao` — "oi" → sem `call_jev_trader`, sem recomendação, sem disclaimer
2. `petr4_swing_hold` — "vale comprar PETR4 pra swing?" → `hold` (gate evento), `confidence` presente, `Fontes:` e disclaimer
3. `vale3_venda` — mock venda (weighted baixo) → `venda`
4. `ticker_invalido` — "vale comprar XYZ?" → erro `Ticker inválido` (before_tool_callback)
5. `followup_15pct` — sessão 1 PETR4 8% → sessão 2 "e se aumentar pra 15%?" → recall `load_memory` + `hold` por `risco_excessivo`
6-8. `web_search_*` — PETR4 sem `noticias_7d` → `google_search` chamado, 3 variações de notícia
9-11. `gate_*` — confidence baixa (0.45), risco_excessivo 0.85, informacao_insuficiente 0.8 → todos `hold`
12. `modo_live` — mesmo que #2 mas com `TYPESAFE_API_KEY` real, valida `model` começa `jev-`
13-15. `interface_*` — repete #2 via CLI e Web UI (Playwright)

### 3. Camadas E2E

**A. Runner (API) — mais estável, sem LLM externo:**
```python
from google.adk.sessions import InMemorySessionService
from google.adk.memory import InMemoryMemoryService
from google.adk.runners import Runner
runner = Runner(agent=root_agent, app_name="e2e", session_service=..., memory_service=...)
async for event in runner.run_async(user_id="e2e_user", session_id="s1", new_message=Content(...)):
    ...
assert "Recomendação" in final_text and "CVM" in final_text
```

**B. CLI — `adk run`:**
```bash
echo "vale comprar PETR4?" | .venv/bin/adk run jev_conversacional
# ou
.venv/bin/adk run jev_conversacional "vale comprar PETR4?"
```
Assert stdout contém `hold`/`compra`/`venda` + `confidence`.

**C. Web — Playwright:**
- `conftest` sobe `adk web --port 0` (porta efêmera) via `subprocess.Popen`, aguarda `http://127.0.0.1:{port}` 200.
- Playwright `page.goto("http://127.0.0.1:{port}")`, seleciona `jev_conversacional` no dropdown (seletor `select` superior esquerdo — conforme doc web UI), envia mensagem no input chat, aguarda `response` bubble.
- Asserts: `Recomendação`, `Fontes`, `Disclaimer` visíveis; `load_memory` e `google_search` aparecem no trace `Events` (opcional screenshot).

### 4. Mocks e Live
- **Mock default:** `TYPESAFE_API_KEY` ausente → `call_jev_trader` usa `mock_answers` (já implementado); `google_search` stub retorna 3 notícias fixas Reuters/Valor/RI.
- **Live:** quando `jev_conversacional/.env` contém ambas as chaves (já inseridas), `pytest -m e2e --env=live` roda cenários 12 sem mock; `skipif not os.getenv("TYPESAFE_API_KEY")`.

### 5. Execução
```bash
uv run pytest tests/e2e -m e2e --env=mock -v --html=report.html  # CI
uv run pytest tests/e2e -m e2e --env=live -v  # local com chaves
.venv/bin/adk web --port 8000 &  # manual exploratório
```

## Validation Plan

- **Unit (já verde):** `pytest tests/test_jev_trader.py tests/test_conversacional_adk.py -v` 12 passed.
- **Smoke param:** `.venv/bin/python -c "from jev_conversacional.agent import root_agent; assert root_agent.model=='gemini-3.8-flash'"` → 0.
- **E2E mock (CI):** `uv run pytest tests/e2e -m e2e --env=mock -q` → 15 passed, `report.html` gerado, nenhum `TYPESAFE_API_KEY` real chamado (ver `usage input_tokens==0`).
- **E2E live (local com chaves já inseridas):** `uv run pytest tests/e2e/test_e2e_runner.py -k petr4_swing --env=live -s` → `model` começa `jev-`, `probabilidades` soma 1.0, `google_search` retorna fontes reais.
- **Interface manual:** `adk web --port 8000` → abrir `http://localhost:8000`, selecionar `jev_conversacional`, enviar "vale comprar PETR4?" → resposta contém `Recomendação: HOLD`, `Fontes:` e `CVM` em <8s.
- **Maior risco:** Playwright flaky por DOM do `adk web` (Dev UI não-prod, seletor pode mudar). Mitigar fixando `data-testid` do input chat e usando `wait_for_selector` com timeout 10s; fallback é validar só camadas Runner/CLI se Web falhar.

## Risks / Rollback

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| `gemini-3.8-flash` inexistente no ADK/Google | `LlmAgent` falha no init | `GEMINI_MODEL` env com fallback `gemini-2.0-flash`; teste smoke falha legível antes do E2E |
| `.env` sobrescrito perde `GOOGLE_API_KEY` | `adk run/web` 401 | Editar `.env` via `edit` com `find` exato de `GEMINI_MODEL`, nunca `write` completo; backup `.env.bak` |
| `adk web` Dev UI muda DOM | Playwright quebra | Seletores resilientes (`textarea`, `button:has-text("Send")`); `test_e2e_web.py` marcado `skip` em CI se porta não sobe |
| `google_search` quota | E2E live sem fontes | Stub mock + cache; live testa 1 cenário só |
| `yfinance` offline | `get_market_data` mock | Já tem fallback mock; E2E valida estrutura, não valor exato |

**Rollback:** `git checkout -- jev_conversacional/.env.example jev_conversacional/agent.py` + `GEMINI_MODEL=gemini-2.0-flash` volta ao flash anterior; E2E continua verde em modo mock.
